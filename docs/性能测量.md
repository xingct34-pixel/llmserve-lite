# 性能测量口径

已完成两轮真实CPU短文本测量与最终10请求冒烟，结果见测试报告。MockEngine服务层基准单独列出；真实模型质量、长上下文和长期稳定性尚未验收。

`bench/run.py` 每次创建独立本机服务，冷启动完成后预热 3 次，固定输入、输出上限、配置与二进制。当前 mock 基准比较客户端并发 1/2/4/8，每组 24 个请求，输出 32 个模拟片段，片段间延迟 2ms。最后一组可能因在途数上限发生 429，这是预期的过载行为，不是成功样本。

| 指标 | 定义 |
|---|---|
| 客户端端到端延迟 | 发起请求至完整读取 SSE，包括正常结束标记 |
| 客户端 TTFT | 发起请求至收到首个非空文本 delta；包括排队与传输 |
| queue_ms | 服务端接收 Job 至 worker 标记 running |
| execution_ms | worker 开始至生成完成检查；与 HTTP 完整送达不同 |
| prefill_ms | llama 引擎清空状态、模板、分词、分块 prefill 的总墙钟时间；不单独等于纯矩阵计算耗时 |
| decode_ms | 采样/解码/UTF-8 输出回调循环墙钟时间，包括可能的背压等待；不宣称为纯算子吞吐 |
| first_token_ms | worker 开始至首个完整 UTF-8 文本写入 Job 缓冲 |
| 请求吞吐 | 完成的成功请求数 / 该组客户端墙钟时间 |
| 输出吞吐 | 成功请求实际输出 token 总数 / 该组客户端墙钟时间；mock 的单位是模拟片段 |
| RSS / VmHWM / VmSwap | 服务子进程 `/proc/PID/status` 的 KiB 值与高水位 |
| MemAvailable / SwapFree | WSL 系统级 `/proc/meminfo`，不能当作进程指标 |

拒绝、超时、错误和断流不计入成功延迟分位或成功吞吐分子。24 个样本的 p95 只作初步观察，不报告 p99；不同并发下成功样本数量可能不同，不能只看 p95 判断整体服务质量。压测端自身 CPU 时间及机器 load average 记录在 JSON 中；请求、资源采样和日志均可复核。

稳定性测试为连续 30 分钟轻负载：单客户端、16 个模拟片段、2ms/片段、请求间等待约 0.2 秒，另查 healthz，每秒采样一次资源。它验证这组生命周期与数据流的持续运行，不代表真实模型运行 30 分钟，更不代表公网恶意连接压力。内存结论应比较预热后的时间窗口，不能把首次分配的 RSS 增长直接等同泄漏。

后续真实模型矩阵：先固定单并发比较线程 2/4/6；再固定最佳线程比较并发 1/2/4/8。输入长度以套用模板后的 `prompt_tokens` 为准，目标 32/128/512，输出上限 64/128；若需要精确长度输入集，应以固定模型 tokenizer 生成并记录，不使用字符数代替。每组预热后至少 20 次成功请求，记录原始拒绝与失败情况。

资源门槛建议为：0.5B 进程峰值 RSS 优先控制在 1.5 GiB 内；WSL 保持至少约 0.7 GiB MemAvailable，监视宿主机压力，出现持续换页或卡顿即停止该轮实验。本次短文本真实测试峰值RSS低于1.5GiB且无进程Swap；这一结论不外推到长上下文或其他模型。

真实复现命令：`python3 bench/validate_real.py`。它依次创建一个新服务进程、测首请求、再测20次后续请求；不会自动下载模型。首请求并非清空OS页缓存后的冷启动。
