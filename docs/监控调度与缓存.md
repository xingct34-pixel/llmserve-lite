# 监控、负载与CPU前缀缓存

本轮保留现有HTTP/SSE协议和单worker架构，增量增加可验证的CPU能力。默认关闭缓存和额外输出预算。

## 标准监控

- GET /metrics仍返回原JSON，新增固定桶histograms及token累计数据。
- GET /metrics/prometheus提供Prometheus 0.0.4文本格式，使用seconds单位，不把request_id、提示词或模型本地路径作为标签。
- accepted/rejected/completed/failed/cancelled/timed_out及HTTP状态分别计数。直方图仅归档成功请求，故障必须同时查看独立计数，不能只看成功p95。
- queue、execution、first_output、prefill_compute、decode使用固定桶，内存不随请求总数增长。first_output是worker开始到完整文本片段入队，不含排队和网络，与客户端TTFT不同。
- 旧prefill_ms继续包含缓存处理、聊天模板、分词和sampler准备。新增prompt_prepare_ms、prefill_compute_ms用于区分准备与实际prefill计算；decode_ms仍含采样、文本转换和回调背压。

```bash
curl http://127.0.0.1:8080/metrics/prometheus
```

deploy/prometheus.yml给出本机抓取配置，deploy/alerts.yml给出拒绝和持续积压告警例子，抓取配置已通过rule_files引用/etc/prometheus/alerts.yml，运行时须将告警文件挂载到该位置。deploy/dashboard.json可导入Grafana并选择Prometheus数据源。这些配套程序没有在当前机器安装；配置存在不等于完成监控系统运行验收。

## 有界等待计算预算

配置queued_output_budget为0时保持旧行为。设置正整数（最多16384）时，等待队列内各请求max_tokens之和不能超过预算，超限仍返回429。活动请求不计入等待预算，出队/清理后容量恢复。

这表示最大输出计算承诺，不是准确耗时预测，也不是KV显存/内存容量。当前串行worker中，等待请求还没有独立KV。输入仍由真实聊天模板及tokenizer验证上下文；不声称在HTTP线程中提前进行模型分词。FIFO不变，不声称实现了全局算力调度。

## 混合负载与SLO

```bash
python3 bench/traffic.py --binary build/mock/llmserve --config configs/mock.json --samples 24 --interval 0.03 --clients 8 --output results/traffic-mock.json
python3 bench/traffic.py --binary build/cpu/llmserve --config configs/cpu.json --samples 12 --interval 0.15 --clients 8 --ttft-slo-ms 3000 --latency-slo-ms 8000 --output results/traffic-real.json
```

工具交替发送长短输入，按计划间隔到达，最多16个发送线程；达到客户端容量时记录client_capacity未发送样本，不在线程池无限排队。记录计划到达与实际发送的延迟，offered TTFT/latency包含此客户端延迟。成功、429、其他失败和客户端未发送都保留；SLO达标率的分母是全部计划请求。Goodput是同时满足TTFT及总延迟门槛的成功请求数/整轮墙钟时间，门槛由测试者显式指定，不是普适行业标准。

客户端TPOT=(完整响应耗时-首次文本耗时)/(输出token数-1)，仅在输出超过1 token时计算；包含末尾终态/网络开销。SSE片段不等于token，不冒充纯算子逐token延迟。Mock统计仅表示模拟服务行为。

## 有界前缀缓存实验

在项目本地配置中设置prefix_cache_tokens，例如256；必须小于context_tokens，只允许真实llama引擎，默认0关闭。不更换模型、不增加模型副本、不保存磁盘会话。

实现只比较上一条成功请求与当前请求的实际模板化token前缀，最多保留配置上限；至少重算最后一个输入token以获得正确logits。共同前缀以后的旧生成KV必须删除，删除失败就清空重算。异常或取消使缓存元数据失效。单个context限定KV容量，元数据有界。

缓存命中用cached_prompt_tokens报告，原prompt_tokens仍是完整输入长度。缓存主要减少重复Prefill，不保证Decode速度提高，也不保证CPU总吞吐提高。本机Q4_K_M实验已观察到分批计算后的数值及后段贪心文本差异，不能承诺缓存开关前后逐字一致。回归明确记录same_text_as_full_prefill，而不把它全部写成true；缓存失效后的全量计算则严格比较隔离基线。该实验默认关闭，要求逐字回归的场景须保持关闭，实际数据见验收报告。

此实验服务于单用户本机演示，缓存不具备多租户隔离机制，不向公网开放。连续批处理、跨请求多序列KV调度、PagedAttention、分布式调度均未因此实现。

## 容器边界

deploy/Dockerfile只构建无模型Mock服务，不下载权重，不把宿主机编译目录或敏感配置传入构建上下文；使用非root用户和SIGTERM。Linux可使用：

```bash
docker build -f deploy/Dockerfile -t llmserve-mock:local .
docker run --rm --network host --memory 256m --cpus 2 llmserve-mock:local
```

服务仍绑定127.0.0.1。这里的host网络只面向合适的Linux Docker环境，不能假设Windows Docker Desktop默认同样可用。构建阶段会在容器镜像内安装编译依赖，不修改宿主机系统软件；当前机器没有Docker，实际容器验收交由GitHub的独立Mock container smoke工作流，只有工作流成功后才能宣称该路径通过。基础镜像标签和发行版包并非完整字节可复现的锁定供应链。

真实模型容器、Kubernetes/KServe、自动扩缩容、GPU/NPU、gRPC和多租户鉴权不在当前完成声明中。
